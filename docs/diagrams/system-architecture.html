awd — system architecture

workflow runtime + shared canvas + agent panes

Where state lives

  • • .awd/events.ndjson — every workflow event, append-only; status and replay are derived from it
  • • boards/<id>.changes.ndjson — every board change with its before; the snapshot is rebuildable
  • • .awd/mail/*.json — the contract between the runtime and an agent in a pane
  • • Nothing lives in memory only; restart = replay

Who talks to whom

  • • Browser ↔ canvas over WebSocket (changes, presence)
  • • Claude Code → canvas through the MCP stdio bridge → HTTP
  • • Trello → tunnel → runtime webhook → event
  • • Runtime → herdr socket → pane agent → mailbox file back
  • • Runtime → claude -p or the Messages API for structured output

What is swappable

  • • LLM / tool: WorkerRuntime — claude-code, anthropic, cli, herdr, fake
  • • Agent channel: AgentChannel — herdr today, tmux tomorrow
  • • Storage: EventStore / BoardRepository — file or memory, sqlite next
  • • Board: only the trigger's data: mapping and script steps
