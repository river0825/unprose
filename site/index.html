The idea

Long text is hard to align on. A board is not.

You can't point at a sentence in a wall of agent output and say "this part". On a board you can: select a box, a line or a whole diagram, and ask.

  • Files are the truth

    The board is drawn from design/*.yaml files in your repo. Every change is a normal git diff.

  • The agent edits, you direct

    You ask and decide; the agent does the typing, lints the file and redraws the board.

  • Board edits are proposals

    A dragged wire or an edited line waits for your OK. The canvas itself never writes a file.

  • Your layout stays

    Redrawing keeps where you put things, and what you deleted stays deleted.

  design/*.yaml  ──draw──▶  board  ──you comment──▶  agent
        ▲                                              │
        └──────────────── edits the file ◀─────────────┘
The diagrams

From a process to a plan to the work, on one board.

Each diagram is one file in design/. Several share a board, and traces link them: this story comes from that command, this card from that story.

Wireframes and UI mocks

Sketch what is on a page with a wireframe, or show what it will look like with a UI mock: real components, real copy, a device size, light or dark. Comment on one button, like on a Figma frame.

Tell one concrete scenario in pictographic sentences. Play story replays it sentence by sentence, with auto-play and a ghost mode. Import and export with Egon.io.

Workflows

Describe an agent pipeline as data: steps, the events between them, who runs each one. Lint it, golden-test it and run it.

<name>.workflow.yaml

In Claude Code, type /unprose: to start one: /unprose:eventstorm, /unprose:storymap, /unprose:kanban, /unprose:wireframe, /unprose:mockup, /unprose:domain-story. Codex and other MCP agents get the same as MCP prompts.

The conversation loop

Comment, discuss, agree. Then the file changes.

Every conversation is anchored to what you selected: an item, a selection, a few lines of a file, or the whole board.

  1. You commentSelect a box and ask in the Chat tab, or leave a note on the board.
  2. The agent readsIt sees exactly what changed and what your comment is about.
  3. It answers or proposesA reply in the same thread, or a concrete change to discuss.
  4. You agreeNothing is applied until you say yes in the thread.
  5. The file changesThe agent edits the yaml, lints it, and the board redraws.

Changes on the board are proposals

Drag a wire, edit lines in the source dialog, delete a drawn item: it shows as a proposal that is not in the file yet. Ask the AI to review it with you; once you agree, it edits the file and the proposal disappears.

Every message shows where it is:

  • Sent
  • Seen by agent
  • Agent is working…
  • Needs you

Comment on any lines

Open the file or prompt behind a diagram in a large view with syntax highlighting, select lines and ask about exactly those.

Several agents, one board

Bring Claude, Codex and a cloud agent to the same discussion.

Agents on another machine and cloud agents connect to the canvas's own MCP endpoint, with your approval. Clear rules decide who answers, who is asked and who may change the files.

  • Remote agents via /mcp

    Point a client at https://<your canvas>/mcp. It shows a one-time pairing code; every open canvas page asks "agent wants to connect". Type the code and press Allow. Or make a read-only or read-and-draw token. Revoke any time.

  • @mentions

    Pick who answers a board with Answered by. Write @codex-b in a comment to send that thread to one agent. Agents ask each other the same way, and pause after a few messages without you.

  • File holders

    Each diagram shows who holds its files: Files: team-notes · held by codex-b. A remote agent can't touch your files, so it proposes a diff; the holder applies it after you agree.

  • Shared context

    A board's Context note tells every agent what was discussed before it joins. Each agent's changes carry its name.

Another agent's "agree" is never your consent: only you approve a change in the thread. Setup per client, and a two-machine example: docs/agents-setup.md.

Install

Up and running in a few minutes.

You need Node.js 20+ and git. No npm install: the repository ships a ready-to-run build.

Claude Code plugin

claude plugin marketplace add river0825/unprose
claude plugin install unprose@unprose

Adds the MCP tools, the Unprose skill and the /unprose: commands. At the start of each session it makes sure a canvas runs on http://localhost:4400, and restarts it on the new version after an update.

Codex

git clone https://github.com/river0825/unprose
node unprose/scripts/canvas.mjs

Then add the MCP server to ~/.codex/config.toml and copy AGENTS.md into your project:

[mcp_servers.unprose]
command = "node"
args = ["/path/to/unprose/scripts/mcp.mjs"]
env = { AWD_CANVAS_URL = "http://localhost:4400" }

Any MCP agent

A stdio server: command node, argument /path/to/unprose/scripts/mcp.mjs, environment AWD_CANVAS_URL=http://localhost:4400.

Or, on another machine or in the cloud, connect over HTTP and approve with a pairing code:

claude mcp add --transport http unprose \
  https://<your canvas>/mcp

Details and caveats per client: docs/agents-setup.md. Then ask your agent: "Draw an EventStorming of our signup flow in Unprose."
